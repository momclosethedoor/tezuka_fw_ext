# OBS-004 — поток наблюдений и собственное avg/peak

Дата: 2026-11-12. Pentium / Windows; один исполнитель, без агентов.

**Итог: PARTIAL — доступная реализация выполнена и сохранена.**
RAM-адаптер, устранение вызова legacy IRQ в native, потоковый ARM-накопитель и
его включение в native runtime реализованы в Rust. Изменённый Rust **не собран и
не исполнен**: на Pentium отсутствуют rustc/cargo, ARM-only CI в этом проходе по
указанию Глеба не запускался. Это подготовленный код, а не принятый live ARM.
Python-читатель и установленный минимальный хостовый вход строк проверены
локально, включая сохранённые реальные bytes. Зависимость от нового ELF не
отменяет этот результат; аппаратные пункты ниже остаются NOT RUN.

## Реализованный путь

### RAM и завершение native

Глеб явно уточнил: **544 слова возникают только при RAM-загрузке; при штатной
полной прошивке сдвига нет.** Это принятое уточнение Глеба, а не повторное
аппаратное измерение этого прохода. ABI/нормировка/порядок bins не менялись.

По умолчанию `ram_load_test=false`: обычный строгий native путь без поправки.
При явном `true` требуется `series_windows=8`, завершение loss-free серии восьми
слотов с first_slot=0. Вся стабильная серия копируется до rearm; после копирования
повторно сверяется completion. Из линейной копии собираются семь целых записей
с позиции `(4096-544)*8=28416` байт, через границы соседних слотов, затем идёт
неизменный строгий parser. Заголовки, контекст, последовательность и последняя
seq проверяются до публикации серии. Никакого переноса хвоста между сериями
или склейки slot7→slot0. Другой completion — явная ошибка, не эвристика.

Краевые фрагменты суммарно32768 байт/серию исключаются как `ram_edge_records=1`,
отдельно от аппаратного native lost. Дополнительная сырая копия262144 байт;
буферы повторно используются. Новая серия не использует старые DDR bytes.
Python counterpart `native.ram_records` воспроизводит проверенную сборку из
`check_raw.py`; в локальном regression использован исходный raw-three.bin.

Native `App::run` теперь запускает HTTP и counter-based source, без legacy
InterruptHandler.run/RecorderFinishWaiter.run. Проверен код fpga.rs:
конструктор создаёт UIO/Notify, а irq_enable/irq_wait вызываются только из run.
Потому native не запускает прежнее blocking uio_read. Runtime логирует ошибку
до своего Drop и teardown отправителей. Остаётся прежний bounded drain до15s.
Reset/kill/restart как исправление не добавлялись; boot/counters/lease/marker
проверки сохранены. Само отсутствие зависания новым ELF ещё не измерено.

### Накопление и идентичность

`observation_accumulator.rs`: один ограниченный накопитель, float64 суммы и
float32 максимумы, вход — уже нормированный nint=1. Явный
`accumulate_windows=1..65536`; он не зависит от dwell, settling или UI fps.
Никакого K(Fs), второго деления на nint или peak от средних групп.

Группа содержит пригодные последовательные FFT одной эпохи и descriptor/grid.
Gap/dirty/epoch0/NaN/sмена контекста заканчивают текущую группу; непустая группа
выдаётся частичной с честным nint, непригодное окно в неё не входит. Обычный
конец источника flush-ит остаток. Дубликаты/порядок/reset проверяются; fatal
ошибка может прервать pending partial, не подставляя данные. Новый источник
требует finish старого накопителя и новой пары accumulator/encoder/UUID.
Статический native runtime горячую замену источника не вводит.

Сохраняется single-plane nint=1: оба новых accumulation поля отсутствуют.
В avg+peak обязательно отдельное `derived_capture_id != capture_id`. GOBS1
mode3 — mean[N], peak[N] **одной** группы. Derived seq — номер группы с0 до
выходных потерь, в отдельном UUID; это не raw hardware seq. Raw-происхождение
остаётся в конфигурации/READY логе; source3 наследуется от аппаратного источника.
epoch/сетка/first_tick относятся к реально участвующим FFT, nint фактический.
Семантика явно добавлена в существующий OBSERVATION-V1; новых wire-полей нет.

На4096 bins накопитель хранит49152 байта массивов sum+peak, независимо от target
и длительности; output32768 байт плюс существующие fixed buffers. Это расчёт
размеров по коду, **не аппаратный RSS**. Очередь остаётся8 групп, максимум2
клиента; per-FFT истории нет. Логи раздельно дают recorded/lost/RAM edges,
decoded/accepted/unusable/input gaps, группы, contention drops и client missed.
Пропуски unselected FFT и discarded RAM edges не называются DMA loss.

### Читатель и хост

Существующий `live.py` получил явный `--profile avg-peak`, счётчик contributing_ffts
и опциональный `--host-rows-root`. Default single по-прежнему требует nint=1.
Новая группа считается одним измерением, обе плоскости читаются совместно.

В `C:/proj/goofy_v2` применены только два файла:

- `sdr/dsp/rows.py`: `append_precomputed` непосредственно закрывает одну строку
  из готовых mean/peak; только10log10 для отображения, без K(Fs), /nint и DC edit.
- `sdr/source/gobs_rows.py`: небольшой bridge для уже проверенного GOBS frame,
  один UUID/последний ID+signature, дубликат показа не создаёт строку. Нет нового
  socket owner, потока, сервиса или продуктового CLI. Инструментальный reader
  вызывает bridge в своём существующем loop до следующего borrowed payload.

Оригинал rows.py сохранён в `evidence/obs-004/original/rows.py`, SHA256
`0c70c3ca729df57687d656c28928ffc92626957f091104473eca40b3b957604f`.
Изменённый SHA256 `69e23f408c155b54c985913ac9dc2fe87096b9b308a8f7f8a4c80e219a553fb8`.
Новый bridge SHA256 `174e353087b4b1de7cbce60886c8e6819caa4dfbd1b5a94e4f129afb7e691a16`.
`host-manifest.json` содержит хеши. Patch apply/reverse проверен на отдельной
копии до побайтного восстановления; git core.autocrlf=false обязателен.
Первый roundtrip выявил преобразование LF→CRLF локальным git; до правки настройки
host не записывался. Guarded installer затем успешно применил проверенные bytes.
Откат только этих файлов: существующим venv выполнить
`evidence/obs-004/install_host.py --restore`; скрипт сначала проверяет оба текущих
хеша, возвращает backup и удаляет только собственный неизменённый новый модуль.
Фактический откат рабочего хоста не выполнялся, обратимость проверена на копии.

Полное подключение GUI/классификатора не выполнено: следующий hook — выбор
DeviceLink/Source в `sdr/source/link.py`, row-producing ветка `sdr/loop.py` до
rows.feed_lin/feed. Требуются source-specific immutable cls_desc `(d,e,g,analog)`
через remember_descriptor и явная привязка source clock к времени хоста.
Текущий bridge передаёт source-clock seconds и nint*N/Fs, не arrival/dwell.
Существующие header/storage ширины не расширялись: host hook явно отказывает
при nint>65535, N>32768, gen>u32, epoch>i64::MAX. GOBS reader сохраняет полные
границы wire. Это предел минимального host hook, не требование менять ABI.
Штатный источник PL-5b и его настройки выбора оставлены рабочими.

## Конкретное продолжение

1. **Следующая затратная зависимость — один существующий ARM-only CI**, а не
   PL/полная firmware сборка. Код: firmware `ef097fc03b01d2d58cfdc05353cbc7bc4283ed39`
   или более новый documentation-only head ветки obs-004 с тем же source.json.
   Запуск только следующим явно разрешённым действием Глеба:

   ```powershell
   gh workflow run main.yml -R momclosethedoor/tezuka_fw_ext --ref obs-004 -f boards=nano -f mode=arm-only -f release=false
   ```

   Он разблокирует компиляцию/исполнение std-only Rust tests (включая4 accumulator,
   2 RAM), Python cross-check avg-peak.gobs, сборку actual ARM Runtime/App и QEMU
   offline-проверку single/avg config с негативными случаями. Runtime unit tests
   в native_runtime.rs дополнительно требуют полного crate test окружения; один
   ARM release build сам по себе их не исполняет. На доступной dev/CI среде:
   `cargo +1.94.0 test --lib native_runtime::tests` из maia-httpd, с системными
   зависимостями существующей сборки; на Pentium toolchain не устанавливать.
2. Скачать именно новый run/attempt: существующей командой `gh run download RUN_ID
   -R momclosethedoor/tezuka_fw_ext -D artifacts/RUN_ID-attempt-N`; сверить manifest,
   head/source tree hash, SHA256 actual maia-httpd и результаты QEMU. Прежний
   ELF43213696707 не способен проверять OBS-004. Не использовать full-mode image:
   принятая PL остаётся370d03a, XSA в firmware по-прежнему PL-5b.

   порта и transcript на Pentium. `pl_uart_obs.sh load/status/restore` **только через

   `f9964280f463f545ac7f25d7f1a9e441a20a4f6c50a35e34c222dbcc7ef402b4`.
