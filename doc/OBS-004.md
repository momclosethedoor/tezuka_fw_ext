## Реализованный путь

### RAM и завершение native

Глеб явно уточнил: **544 слова возникают только при RAM-загрузке; при штатной
полной прошивке сдвига нет.** Это принятое уточнение Глеба, а не повторное
аппаратное измерение этого прохода. ABI/нормировка/порядок bins не менялись.

По умолчанию `ram_load_test=false`: обычный строгий native путь без поправки.
При явном `true` требуется `series_windows=8`, завершение loss-free серии восьми
слотов с first_slot=0. Вся стабильная серия копируется до rearm; после копирования
повторно сверяется completion. Из линейной копии собираются семь целых записей
с позиции `(4096-544)*8=28416` байт, через границы соседних слотов, затем идёт
неизменный строгий parser. Заголовки, контекст, последовательность и последняя
seq проверяются до публикации серии. Никакого переноса хвоста между сериями
или склейки slot7→slot0. Другой completion — явная ошибка, не эвристика.

Краевые фрагменты суммарно32768 байт/серию исключаются как `ram_edge_records=1`,
отдельно от аппаратного native lost. Дополнительная сырая копия262144 байт;
буферы повторно используются. Новая серия не использует старые DDR bytes.
Python counterpart `native.ram_records` воспроизводит проверенную сборку из
`check_raw.py`; в локальном regression использован исходный raw-three.bin.

Native `App::run` теперь запускает HTTP и counter-based source, без legacy
InterruptHandler.run/RecorderFinishWaiter.run. Проверен код fpga.rs:
конструктор создаёт UIO/Notify, а irq_enable/irq_wait вызываются только из run.
Потому native не запускает прежнее blocking uio_read. Runtime логирует ошибку
до своего Drop и teardown отправителей. Остаётся прежний bounded drain до15s.
Reset/kill/restart как исправление не добавлялись; boot/counters/lease/marker
проверки сохранены. Само отсутствие зависания новым ELF ещё не измерено.

### Накопление и идентичность

`observation_accumulator.rs`: один ограниченный накопитель, float64 суммы и
float32 максимумы, вход — уже нормированный nint=1. Явный
`accumulate_windows=1..65536`; он не зависит от dwell, settling или UI fps.
Никакого K(Fs), второго деления на nint или peak от средних групп.

Группа содержит пригодные последовательные FFT одной эпохи и descriptor/grid.
Gap/dirty/epoch0/NaN/sмена контекста заканчивают текущую группу; непустая группа
выдаётся частичной с честным nint, непригодное окно в неё не входит. Обычный
конец источника flush-ит остаток. Дубликаты/порядок/reset проверяются; fatal
ошибка может прервать pending partial, не подставляя данные. Новый источник
требует finish старого накопителя и новой пары accumulator/encoder/UUID.
Статический native runtime горячую замену источника не вводит.

Сохраняется single-plane nint=1: оба новых accumulation поля отсутствуют.
В avg+peak обязательно отдельное `derived_capture_id != capture_id`. GOBS1
mode3 — mean[N], peak[N] **одной** группы. Derived seq — номер группы с0 до
выходных потерь, в отдельном UUID; это не raw hardware seq. Raw-происхождение
остаётся в конфигурации/READY логе; source3 наследуется от аппаратного источника.
epoch/сетка/first_tick относятся к реально участвующим FFT, nint фактический.
Семантика явно добавлена в существующий OBSERVATION-V1; новых wire-полей нет.

На4096 bins накопитель хранит49152 байта массивов sum+peak, независимо от target
и длительности; output32768 байт плюс существующие fixed buffers. Это расчёт
размеров по коду, **не аппаратный RSS**. Очередь остаётся8 групп, максимум2
клиента; per-FFT истории нет. Логи раздельно дают recorded/lost/RAM edges,
decoded/accepted/unusable/input gaps, группы, contention drops и client missed.
Пропуски unselected FFT и discarded RAM edges не называются DMA loss.
